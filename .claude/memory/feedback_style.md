- Show changes as diffs against the base version
- Never delete user's comments in code
- Don't overthink requests — do exactly what's asked
- Don't add optimizations beyond what's requested
- Separate planning/discussion from code generation (user says "plan mode" or "don't generate diffs")
- User wants every hypothesis and dead end documented for blog posts
- Use "ultrathink" as a signal to think deeply before responding

**Why:** User is writing blog posts about the process and values the narrative of what was tried and what failed, not just the final result.

**How to apply:** When making changes, document what was tried and why it did/didn't work. When the user says "plan mode", discuss without generating code.
